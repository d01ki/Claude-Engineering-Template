# Reflect

1. Identify a completed task with real verification evidence.
2. Separate repeatable technique from project-specific details and one-off guesses.
3. Check whether existing rules, tests or skills already encode the lesson.
4. Draft a concise reusable skill or documentation change only if there is recurring value.
5. Avoid recording secrets, customer data, or unverified claims.
6. Present proposed policy/skill changes for human review before making them authoritative.
7. Link the lesson to relevant test, PR or decision evidence.
