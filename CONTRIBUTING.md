# Contributing

1. Open an issue or write a short plan for non-trivial changes.
2. Keep CLAUDE.md concise; scope details into rules or skills.
3. Make PRs small and describe acceptance criteria and verification.
4. Never commit credentials, local settings or private data.
5. Run the checks appropriate to your project's stack.
6. Require approval for destructive changes and deployments.

This template intentionally does not prescribe a framework or package manager.
